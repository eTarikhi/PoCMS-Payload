1.3 Velocity and momentum

Velocity is measured as estimated effort delivered per calendar day, using the roadmap’s unit so planned and requested work are comparable. Day one carries the pre-analysed roadmap (41.1 engineer-days). From 17 Oct, when the work became owner-driven change requests, daily velocity was 11.5 (17 Oct), 9.0 (18 Oct), 19.5 (19 Oct): median 11.5, total 40.0. These three days are the basis of the forecasts.

Momentum reading. Throughput rose again on 19 Oct (19.5 engineer-days), but all of its planned work (17.5) landed before 06:13. The next two sessions handled a production build failure, the owner’s request to undo that fix, and a Page speed widget that did not work for the owner (fixed 19 Oct 23:47, about 18 h after it shipped). The pattern is a loss of flow on integration and deployment issues, not a drop in delivery capacity; restoring green CI and setting the Vercel variables removes its two causes.

2.3 Dependencies

  • Jobs before scheduling. Payload’s scheduled publish creates jobs and never runs without a job runner [1], so E4 is also a prerequisite of the content release. On Vercel the runner is a cron call to Payload’s jobs endpoints, protected by CRON_SECRET; on the Hobby plan each cron job runs at most once a day, within the hour [2], which suits daily and weekly maintenance.
  • Migrations before new collections. There is no src/migrations; production receives schema changes only through a development-mode push. Roles, trash and dashboard changes already depend on it, and E4/E5 add collections.
  • Terminal after System page. Both need the same environment detection and capability gating; the Terminal also needs a short security review.
  • Payload 4 after quality gates. The visual-regression suite in CI is the safety net for the token re-mapping in P7.

Appendix

A. Method and definitions

  • Commits and lines come from git log -M --numstat on arena/1e75852c-pocms-payload at adff4e0. Authored lines exclude generated files (pnpm-lock.yaml, schema.graphql, payload-types.ts, payload-generated-schema.ts, importMap.js, nav-icons.css), lockfiles and binaries. Renames count only changed lines. Areas are assigned by path (see scripts/progress-report/collect.mjs).
  • Time: commits are placed at their committer time and bucketed into calendar days in Asia/Tehran (UTC+03:30). Agent commits carry UTC timestamps, the owner’s +03:30; the report uses the same zone for both.
  • Origin: commits with UTC author and committer times are the agent’s; the rest are the owner’s (all commits use the owner’s git identity).
  • Effort and velocity: ideal engineer-days for one senior engineer. Roadmap phases use the midpoint of the plan’s range, scaled by the completion of their non-optional items (done or changed = 1, partial = 0.5, not started = 0). Other deliverables carry the author’s estimate on the same scale (milestone table in §1.1). These estimates are the implementer’s own and have not been reviewed independently. Velocity is effort delivered per calendar day; it measures scope against human-effort estimates, not time spent.
  • Forecasts schedule the backlog sequentially in dependency order at the highest, median and lowest observed daily velocity since 17 October, starting 21 Oct; the pessimistic case adds one day for owner decisions. They are estimates, not commitments.
  • Tests: per-commit counts are static declarations (git grep for test( / it( under tests/); today’s run-time counts come from the test runners (vitest, playwright test --list).
  • CI: GitHub keeps 26 runs for this branch, all successful. Run numbers show that 27 runs up to #53 and about three later ones were deleted, so no pass rate is reported. The current red state is from the last observed run.
  • Bundle: compressed transfer sizes from scripts/measure-admin-bundle.mjs against a production build; history from docs/ui-modernization/perf-budget.md, today’s values measured for this report.

B. Reproducing this report

node scripts/progress-report/build.mjs --pdf regenerates the HTML, the PDF and 2026-10-20-progress-data.json from git, gh and scripts/progress-report/model.mjs (plan, statuses, estimates, backlog, risks). Every number in the report is in the JSON file.
