# Admin accessibility: the gate, the gaps, and the manual pass

The admin is held to WCAG 2.2 AA by `tests/e2e/a11y.e2e.spec.ts`, which runs in CI on every push
(`pnpm test:e2e`). It scans seventeen surfaces in both themes, checks the screen-reader structure
axe cannot see, and proves the skip link works from the keyboard. This page records what is
covered, what is still open, and how to run the parts a machine cannot judge.

## What the suite checks

Seventeen surfaces, each in light and dark: the dashboard, the article list, the article create and
edit screens, the orderable Skills list, the media, users, roles and audit-log lists, the folder
browser and the contents of one folder, the site settings global, the component gallery, the system
page, the database page, the scheduled jobs page and the sign-in screen. Every scan uses the
`wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` and `wcag22aa` tags; only serious and critical findings
fail the build.

Alongside the axe rules, every surface must have exactly one main landmark, exactly one non-empty
`<h1>`, a document title, `<html lang>` and `<html dir>`. Every admin screen with a sidebar must
also start with the skip link, and its `href` must resolve to the main landmark. A separate
keyboard test presses Tab from the top of the dashboard (the skip link takes focus and is on
screen), then Enter (focus lands on `#pocms-main`), in both themes.

The scan writes `test-results/a11y-light.json` and `test-results/a11y-dark.json`; CI uploads them
with the visual captures. Each file lists every scan, including the allowlisted findings, so a
reviewer can see the whole picture rather than only the failures.

## Fixed in this pass (2026-10-21)

Each of these was a real finding on the seeded content, not a hypothetical:

| Finding | Where | Fix |
| --- | --- | --- |
| No main landmark on the dashboard or any list | every screen but document views | `AdminDomFixes` marks the view element after the header as `role="main"`, or reuses the page's own `<main>` |
| No way to skip the sidebar | every screen with a sidebar | the same component adds a skip link as the first element in `<body>`, visible when focused |
| No `<h1>` on the dashboard | `/admin` | `beforeDashboard` renders a visually hidden "Dashboard" heading |
| No heading at all on sign-in | `/admin/login` | `beforeLogin` renders a visually hidden "Sign in to PoCMS" heading |
| Row and select-all checkboxes had `aria-label=""` | every list with bulk actions | named in the DOM ("Select row", "Select all rows on this page") |
| Icon-only document controls had no name | edit screens with a file or an optional date | named in the DOM ("More document actions", "Edit file", "Remove file", "Clear date") |
| Hidden select chevron and clear control were focusable | every relationship field and form | taken out of the tab order, as `aria-hidden` intended |
| Tab row was a `<ul>` of `<div>`/`<a>` | every edit screen and global | `role="presentation"` when it has no list items |
| Versions tab label hid its visible text | edit screens of versioned collections | label dropped; the visible "Versions 1" is the name |
| Sort-label text at 2.6:1, upload hints at 3.65:1, upload meta at 3.65:1 | list headers, create/edit screens | the muted token (5.4:1 light, 7.5:1 dark) |
| Sort arrows and the date clear button were 20px | list headers, date fields | 24×24 CSS pixels (WCAG 2.5.8) |
| Inactive image-source tab measured 2.59:1 in dark mode | article and project forms | `acn:bg-transparent` over Payload's default button fill |
| Folder view toggles (grid/list) and the folder "…" menu had no name | `/admin/browse-by-folder`, folder contents | named in the DOM ("Grid view", "List view", "Folder actions") |
| Folder card thumbnails had no `alt` (14 nodes) | folder contents | `alt` from the card's file name, in the DOM (Payload does not pass the media document's `alt` to the card) |
| "Create folder" was a `<div type="button">`, so no focus and no button announcement | folder browser | the DOM fix adds `role="button"`, puts it in the tab order and forwards Enter/Space |
| Section titles ("Folders", "Documents") and the "Media" chip were under 3:1 | folder browser, folder contents | the muted token, and the chip's 50% opacity removed |
| SEO plugin: instruction lines at 2.6:1, length pills white on red/orange/green (1.9–4:1) | article create/edit, site settings | marked in the DOM; the muted token for the notes, darker fills with white text (7.5:1+) for the pills |
| SEO plugin: the search-result preview is a mock (`pointer-events: none`) but its links were focusable — one unnamed, one under 24px | article create/edit, site settings | the preview is `aria-hidden` and its anchors lose `href` and the tab stop |

`src/components/admin/providers/AdminDomFixes/` holds the DOM fixes, one module per upstream
component, each with a comment naming the markup and the Payload version. They only add or remove
the attribute that is wrong, so an upgrade that ships the fix itself wins. Unit tests for all of
them are in `tests/int/admin-dom-fixes.int.spec.ts`.

## Known upstream gaps

These are Payload's own markup and have no config slot or safe DOM fix. The suite allows them by
rule and maximum node count, and **fails when one disappears**, with "remove it from KNOWN", so the
list cannot rot. They are re-checked on every Payload upgrade.

| Surface | Rule | Nodes | Component | Why it is left alone |
| --- | --- | --- | --- | --- |
| dashboard | `label` | 1 | `dashboard-breadcrumb-select` (ReactSelect) | Payload does not pass a label to the combobox; there is no config slot for the breadcrumb |
| article create | `label` | 3 | ReactSelect + two `DateTime` fields | same, plus `react-datepicker`'s inner input has no id for the field label to point at |
| article edit | `label` | 2 | the publish date field | as above |
| Skills list (orderable) | `aria-command-name` | 12 | `SortRow` | the drag handle is a `<div role="button">` with no text, outer and inner, six rows |
| Skills list (orderable) | `nested-interactive` | 6 | `SortRow` | a focusable control sits inside the drag handle; removing it from the tab order would break keyboard reordering, which matters more than the rule |

Two of the older gaps were fixed rather than allowlisted: the paginator arrows (labelled by the same
DOM component) and the row checkboxes (named there too). See the guide's "Known upstream gaps" for
the non-accessibility ones.

## The manual screen-reader pass

The suite proves structure and names; it cannot judge whether a screen *sounds* right. This pass is
**still outstanding** and has to be done by a person with a real screen reader. It takes about
fifteen minutes per reader.

### Before starting

- Run against a production build with the demo content: `pnpm build && pnpm start`, then sign in.
- Seed the test user (`tests/helpers/seedUser.ts`) or use any administrator account.
- Use the current Chrome or Safari, and only the screen reader's own keystrokes to navigate. Keep
  the browser's focus ring visible; do not use a mouse.
- Record what is confusing, not just what is broken. "The chart reads as an unlabelled image" is a
  finding even if axe passes.

### VoiceOver (macOS) / NVDA (Windows) checklist

| Screen | Do this | Expected |
| --- | --- | --- |
| Any admin page | Load with `?` at the end of the URL (skip link), or press Tab once | The first announcement is "Skip to main content" |
| Any admin page | Activate the skip link | Focus moves to main; the reading cursor starts inside the view, not in the sidebar |
| Dashboard | Read from the top | "Dashboard, heading level 1", then the widgets in visual order |
| Dashboard | Move by heading | Every widget is reachable, each announced once, with a sensible name |
| Articles list | Move by table | The table is announced with its row and column counts; sort buttons include their column |
| Articles list | Select a row with Space | The bulk-actions bar and the selection announcement are heard, and the count is correct |
| Article edit | Move through the form | Every field announces its label, its type and its current value; the rich-text editor announces itself |
| Article edit | Reach the hero image | The upload control, "Edit file", "Remove file" and the "…" menu all have names |
| Article edit | Reach the publish date | "Clear date" is announced; focus does not land on the hidden chevron |
| Skills list | Tab to a drag handle | The handle announces itself as sortable, and the arrow keys move the row (keyboard reordering must still work) |
| Sign in | Load the page | "Sign in to PoCMS, heading level 1", then the form; the brand is not read as a heading |

If a screen fails, fix the name or the order where the component is ours. If it is Payload's markup,
add it to `KNOWN` in `tests/e2e/a11y.e2e.spec.ts` **and** to the table above, with the component and
the reason.

## Running it

```bash
pnpm build && pnpm start          # production build in one terminal
pnpm test:e2e -- a11y             # the gate (both themes, 1.2 min)
```

To review a single theme's report: `test-results/a11y-light.json`. The report includes the
allowlisted findings, so a diff between two runs shows exactly which nodes appeared or disappeared.
